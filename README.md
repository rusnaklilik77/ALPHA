# ALPHA — учёт посылок и заработка курьера

> **Обновляешь готовый проект? Обязательно сделай два шага, иначе новые функции не заработают:**
> 1. Firebase Console → Firestore Database → **Rules** → вставь весь файл `firestore.rules` → **Publish**
>    (в нём появились правила для туров `tours` и входящих SOS `sosInbox`).
> 2. `npm install` (добавилась библиотека карты `leaflet`), затем заново задеплой на Vercel.

Веб-приложение на **React + Vite**, которое считает твой заработок как курьера:
сколько посылок отдал и сколько было возвратов каждый день, сколько заработано за месяц
и сколько всего за всё время. Есть графики (по дням и по дням недели), архив по месяцам
(прошлые месяцы не пропадают — доступны отдельными вкладками) и переключение языка
(русский / română / English).

Данные хранятся в Firebase (бесплатный план Spark), у каждого пользователя — свой аккаунт
и свои данные, никто чужого не видит.

## 1. Настройка Firebase (один раз, ~5 минут)

1. Зайди на https://console.firebase.google.com и нажми "Add project" / "Создать проект".
   Название может быть любым, например `alpha-courier`. Google Analytics можно отключить.
2. В левом меню открой Build → Authentication → Get started. Во вкладке Sign-in method
   включи провайдер Email/Password.
3. В левом меню открой Build → Firestore Database → Create database. Выбери любой регион
   (например eur3 (europe-west)) и режим Production mode.
4. Открой вкладку Rules в Firestore и вставь туда содержимое файла `firestore.rules`
   из этого проекта, затем нажми Publish. Это защитит данные — каждый пользователь видит
   только свои записи.
4.1. **Индекс для рейтинга (обязательно, иначе у всех будет 0 посылок).**
   Экран "Режим администратора → Рейтинг" считает посылки сразу по всем сотрудникам
   одним запросом (`collectionGroup` по вложенным коллекциям `entries`). Firestore не
   создаёт индекс для таких запросов автоматически — его нужно включить один раз вручную:
   - Firebase Console → Firestore Database → вкладка **Indexes** → **Single field** →
     найди строку (или добавь новую) для поля `date` и включи для неё переключатель
     **Collection group** в колонке Query scopes, либо
   - через Firebase CLI: `firebase deploy --only firestore:indexes` (в проекте уже есть
     готовый файл `firestore.indexes.json`).
   Пока индекс не создан (или ещё строится — обычно 1–2 минуты), рейтинг будет
   аккуратно показывать сообщение об ошибке вместо молчаливых нулей.
5. В настройках проекта (шестерёнка → Project settings → вкладка General)
   прокрути вниз до "Your apps", нажми на иконку `</>` (Web), задай имя приложения
   и нажми Register app. Firebase покажет объект `firebaseConfig` — эти значения
   понадобятся в следующем шаге.

Firebase бесплатного плана Spark полностью хватает для этого приложения — платить не нужно.

## 2. Ключи Firebase — через переменные окружения

Важно: сами ключи **не хранятся в коде** — это и была причина, по которой билд на Vercel
не работал (в `src/firebase.js` были заглушки `YOUR_API_KEY` и т.д.). Теперь ключи задаются
через переменные окружения `VITE_FIREBASE_*`.

**Локально:**
```bash
cp .env.example .env
```
Открой `.env` и впиши значения из firebaseConfig (шаг 5 выше) в 6 строк:
`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
`VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_APP_ID`.

**На Vercel:** те же 6 переменных нужно добавить в
Project Settings → Environment Variables (для Production и Preview), см. ниже.

Если переменные не заданы — приложение больше не зависает на "Загрузка ALPHA..." молча,
а показывает экран с понятной инструкцией, каких именно переменных не хватает.

## 3. Запуск локально

```bash
npm install
npm run dev
```

Открой адрес, который покажет терминал (обычно http://localhost:5173).

## 4. Деплой на Vercel (тоже бесплатно)

Вариант А — через сайт:
1. Залей эту папку как репозиторий на GitHub.
2. Зайди на https://vercel.com, нажми Add New → Project, выбери свой репозиторий.
3. Vercel сам определит настройки Vite-проекта (Build Command `npm run build`,
   Output Directory `dist`) — менять не нужно.
4. **До первого деплоя** (или сразу после, с редеплоем) открой Project Settings →
   Environment Variables и добавь все 6 переменных `VITE_FIREBASE_*` из шага 2 —
   по одной, значение как в `.env`. Отметь галочки Production и Preview.
5. Нажми Deploy (или Redeploy, если деплоил раньше без переменных).

Вариант B — через терминал:
```bash
npm install -g vercel
vercel
vercel env add VITE_FIREBASE_API_KEY
vercel env add VITE_FIREBASE_AUTH_DOMAIN
vercel env add VITE_FIREBASE_PROJECT_ID
vercel env add VITE_FIREBASE_STORAGE_BUCKET
vercel env add VITE_FIREBASE_MESSAGING_SENDER_ID
vercel env add VITE_FIREBASE_APP_ID
vercel --prod
```

После деплоя сайт будет доступен по ссылке вида https://alpha-xxxx.vercel.app —
можно открывать с телефона, интерфейс полностью адаптивный.

**Если после деплоя видишь экран "Firebase не настроен"** — значит переменные окружения
не заданы или заданы с опечаткой в имени. Проверь Project Settings → Environment Variables
на Vercel и нажми Redeploy (важно именно передеплоить — старая сборка переменные не подхватит).

## 5. Как пользоваться

- Зарегистрируйся с любым email и паролем — это твой личный кабинет.
- Язык интерфейса переключается вверху (RU / RO / EN).
- В кнопке ставки вверху справа можно в любой момент изменить, сколько платят
  за посылку — применится к новым записям.
- Кнопка **"Общий баланс"** вверху открывает окно со сводкой заработка сразу по
  всем месяцам плюс общий итог за всё время.
- Каждый день вводи, сколько посылок отдал, сколько было возвратов и сколько
  получил чаевыми — жми "Добавить". Чаевые сразу прибавляются к заработку за день.
- Счётчик чаевых за всё время всегда виден в углу главной карточки заработка,
  а чаевые за текущий месяц — прямо в строке рядом с "отдано" посылками.
- Можно поставить месячную цель по заработку (кнопка "Поставить цель на месяц") —
  на дашборде появится полоска прогресса, сколько уже заработано от цели.
- Карточка "Лучший день" показывает, в какой день месяца заработок был максимальным.
- Кнопка "Экспорт в CSV" под историей выгружает записи текущего месяца файлом —
  удобно для своей бухгалтерии или отчёта работодателю.
- Вкладки "Месяцы" — переключаются между текущим и прошлыми месяцами, данные
  прошлых месяцев никуда не пропадают.
- Ниже — графики: динамика по дням и по каким дням недели больше посылок/возвратов.
- Список дней и статистика — снизу, записи можно редактировать и удалять.

## 6. Что нового (роли, заставка, туры, SOS, профиль)

**Новые рабочие функции при регистрации** (рядом с «Курьер Приват» и «Курьер Шоп»):

- **Водитель** — есть ставка «€ в день» (кнопка ставки в шапке; при первом входе приложение
  просит её указать). Каждый день водитель нажимает большую зелёную галочку «Отработал сегодня».
  Ниже — календарь месяца: отработанные дни зелёные, любой прошедший день можно отметить или
  снять отметку. Заработок = отработанные дни × ставка за день.
- **Сортировщик** — нет посылок и возвратов, только **часы работы** и **ставка «€ в час»**.
  Каждый день вписывается количество часов (есть быстрые кнопки 4/6/8/10/12 ч).
  Заработок = часы × ставка. Есть график часов по дням.

Обе роли есть в режиме администратора (карточка сотрудника, «По месяцам») и в **Рейтинге**
(вкладки Приват / Шоп / Водитель / Сортировщик: Приват и Шоп — по посылкам, водители — по
отработанным дням, сортировщики — по часам).

**Заставка.** При каждом открытии сайта/приложения на весь экран появляется анимированный
логотип-лев (из присланного фото — `src/assets/splash-logo.png`), после чего открывается приложение.
Тайминги — в `src/components/Splash.jsx` (`SHOW_MS`).

**Телефон.** При регистрации теперь есть обязательное поле «Номер телефона».

**«Доп. сведения» (⚙️ в шапке)** — три вкладки:

1. **Тур** — «Начать тур» → приложение записывает маршрут по GPS → «Завершить тур» → карта
   (OpenStreetMap) с линией пути, зелёным «Старт» и красным «Финиш», километраж и время в пути.
   Все туры сохраняются в историю; администратор видит маршруты сотрудника в его карточке.
   Незавершённый тур переживает перезагрузку страницы.
   Вкладки «Тур» нет у сортировщиков (у них нет маршрутов).
2. **SOS** — выбор получателей красной кнопки (всем зарегистрированным или отдельным людям).
3. **Профиль** — «Мои настройки»: имя, ID, email (только чтение), телефон.

**Красная кнопка SOS** всегда в правом нижнем углу. Получателей нужно выбрать заранее
(без этого кнопка предложит их выбрать). Нажатие → подтверждение → у выбранных людей на весь
экран всплывает красное окно «SOS от пользователя …» с сиреной и вибрацией, телефоном отправителя
(кнопка «Позвонить») и ссылкой на карту с его местоположением. Отправитель может нажать
«Отменить SOS — я в порядке», и окно у получателей исчезнет.

### Важные ограничения (честно)

- **SOS — не настоящая SMS.** Это окно внутри приложения: оно приходит в реальном времени,
  пока у получателя открыт сайт/приложение (в том числе свёрнутая вкладка). Если приложение
  полностью закрыто, ничего не придёт. Чтобы SOS приходил как настоящая SMS или как push при
  закрытом приложении, нужен серверный код: Firebase Cloud Functions + FCM (push) или
  Twilio/другой SMS-шлюз. Это требует платного тарифа Firebase (Blaze) и оплаты SMS.
- **GPS в браузере не пишется в фоне.** На время тура приложение держит экран включённым
  (Screen Wake Lock), но если телефон заблокировали или приложение свернули надолго, запись
  точек остановится. Для записи в фоне нужен нативный плагин в APK (например,
  `@capacitor-community/background-geolocation`) — см. README-APK.md.
- Карта берёт плитки с бесплатного сервера OpenStreetMap — для небольшой команды этого хватает.
  При очень большой нагрузке лучше подключить свой провайдер карт.
- Список сотрудников (имя, ID, телефон) по-прежнему читается любым вошедшим пользователем —
  это тот же компромисс «простота вместо серверных ролей», что описан в `firestore.rules`.
  Сами SOS-сигналы читает только тот, кому они адресованы.
